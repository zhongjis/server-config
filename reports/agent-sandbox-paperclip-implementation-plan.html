01

Milestones

Small, reviewable commits. Do not mix Paperclip plugin enablement, Agent Sandbox install, and runtime hardening in one change.

Slice 0

Confirm installed API surface

Render current Paperclip operator CRD and confirm spec.plugins, spec.adapters.execution, backend, quota, limitrange, and egress fields match operator v0.17.2.

flux/infrastructure/controllers/paperclip-operator.yamlkubectl explainno manifest edits
Slice 1

Enable Paperclip Kubernetes plugin with job backend

Edit the existing Paperclip Instance only: uncomment/add plugins, add @paperclipai/plugin-kubernetes, set execution.mode: kubernetes, set backend: job, add namespace prefix plus quotas/limitranges.

flux/apps/base/paperclip/app/Instance.yamlbackend: jobsmoke only
Slice 2

Validate smoke behavior

After Flux reconcile, run one Paperclip Environment/agent execution. Inspect created namespace, service account, Role/RoleBinding, ResourceQuota, LimitRange, NetworkPolicy, Secret, Job, Pod logs, and cleanup.

flux get kustomizationskubectl get jobsrollback ready
Slice 3

Introduce Agent Sandbox controller

Prefer a HelmRelease if the Agent Sandbox chart is published for the chosen release. Otherwise explicitly approve vendoring the exact release manifest.yaml. Keep extensions separate unless SandboxTemplate, SandboxClaim, or SandboxWarmPool are needed.

flux/infrastructure/controllers/agent-sandbox.yamlpinned releaseCRDs first
Slice 4

Switch to sandbox-cr only after compatibility proof

Change Paperclip from backend: job to backend: sandbox-cr only when the plugin emits the Agent Sandbox API version installed in cluster. If plugin still expects v1alpha1, pin compatible Agent Sandbox or wait for plugin update.

backend: sandbox-crv1alpha1/v1beta1 gateE2E required
Slice 5

Harden isolation and operations

Decide whether shared-kernel pod isolation is acceptable. For hostile code, install/configure gVisor or Kata as k3s runtime classes first. Add monitoring for orphaned namespaces, Jobs, Sandboxes, Secrets, PVCs, and quota pressure.

05

Risks & mitigations

Risk
Sev
Mitigation
Agent Sandbox API mismatch: Paperclip plugin expects v1alpha1, latest Agent Sandbox RC moved to v1beta1.
HIGH
Gate sandbox-cr on a generated Sandbox object test. Pin compatible release or wait for plugin update.
Weak isolation: default k3s pod sandbox shares host kernel.
HIGH
Do not claim hostile-code isolation until gVisor/Kata RuntimeClass is installed, detected by k3s, and tested.
Cilium-only FQDN policy configured on non-Cilium k3s.
MED
Use egressMode: standard first. Adopt Cilium only as a separate network-platform change.
Orphaned execution namespaces, Secrets, Jobs, PVCs, or Sandboxes.
MED
Add cleanup smoke checks before promotion; monitor namespace count and quota pressure.
Flux validation passes but CRD semantics fail at runtime.
MED
Use live CRD explain/dry-run where possible; treat ./flux/scripts/validate.sh as render/schema sanity, not E2E proof.
